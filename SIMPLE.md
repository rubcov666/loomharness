# LoomHarness

[English](README.md) · **Русский**

LoomHarness передаёт ИИ-агенту нужную ошибку, строку кода или число совпадений и сохраняет полный вывод на диске. В сценарии из восьми запросов по синтетическим журналам сборки поиск нужных строк сэкономил **3,69 млн токенов**. Оба способа дали одинаковый итоговый отчёт. [Результаты замера](#замеры-расхода-токенов)

**Версия 1.0.0** · Python 3.11+ · Windows, macOS и Linux · **[Скачать ZIP](https://github.com/rubcov666/loomharness/releases/download/v1.0.0/loomharness-1.0.0.zip)**

## Для чего нужен LoomHarness

1. **Передавать модели меньше токенов.** Из журнала сборки агент получает шаг, на котором произошёл сбой, из отчёта — запрошенные поля. Для уточнений доступен полный файл.
2. **Быстрее находить причину ошибки.** От сообщения об ошибке можно перейти к нужным строкам журнала или к файлу и строке, где объявлена функция.
3. **Умещать долгие расследования в контекстное окно.** LoomHarness оценивает, когда сводка предыдущих шагов сэкономит токены на оставшихся запросах.
4. **Использовать готовые результаты повторно.** Перед новой сборкой или анализом можно узнать, изменились ли исходные данные и сохранённый результат.
5. **Распределять независимую работу в больших проектах.** Для небольшой правки достаточно одного чата. На большом проекте можно назначить ответственных за подпроекты, выбирать модель для каждого этапа и отслеживать проверку и расход токенов по агентам.

## Попробуйте за минуту

Скачайте ZIP по ссылке выше, распакуйте и откройте терминал в папке с `install.py`. Для подключения к Codex выполните команду с Python 3.11 или новее. В Windows используйте `python` вместо `python3`.

```sh
python3 -X utf8 install.py --cli codex
```

При первом подключении откройте `/hooks` в Codex и подтвердите четыре записи LoomHarness. Отправьте в чат проекта `LoomHarness on`. Попробуйте попросить «Найди первый сбой в журнале сборки и покажи строки, которые объясняют причину».

В ZIP входят установщик, инструменты, интеграции и документация. Для установки хватает стандартной библиотеки Python. Тесты самого проекта запускаются для разработчиков в GitHub Actions. [Проверки в CI](https://github.com/rubcov666/loomharness/blob/main/.github/workflows/verify.yml)

## Замеры расхода токенов

### Что измерили за восемь запросов

В двенадцати синтетических журналах сборки находились ограничения, исключения, ссылки на источники и правило повторной проверки для одного отчёта. В замере суммировали вход и выход всех запросов, включая повторную передачу истории, создание сводок и дополнительный поиск. [Методика и точные значения](docs/benchmarks.md#eight-request-build-investigation)

| Как читали журналы | Расход, млн токенов | Экономия относительно полных журналов, млн токенов |
|---|---:|---:|
| Передавали полные журналы в следующие запросы | 3,704577 | — |
| Читали полные журналы и дважды сворачивали предыдущие шаги в сводку | 1,854089 | 1,850488 |
| Искали записи о решениях и отдельно запрашивали правило повторной проверки | 0,011514 | **3,693063** |

### Если выполнить каждую задачу CLI 1 000 раз

Каждая из шести задач измерена отдельно на исходных сообщениях инструментов версии 1.0.0. Для пересчёта объём её вывода умножен на 1 000 в предположении, что входные данные и длина ответа каждый раз одинаковы. За 6 000 таких выполнений вывод инструментов занял бы **1,346 млн токенов вместо 15,008 млн**. Расчётная экономия — **13,662 млн (91,0%)**. [Исходные замеры по каждой задаче](docs/benchmarks.md#six-tool-output-measurements)

| Задача × 1 000 | Исходный вывод, млн токенов | С LoomHarness, млн токенов | Изменение |
|---|---:|---:|---:|
| Разобрать пять журналов тестов | 8,391 | 0,316 | -96,2% |
| Найти объявление функции | 1,455 | 0,081 | -94,4% |
| Узнать статус 60 заданий | 3,956 | 0,746 | -81,1% |
| Посчитать 24 строки с совпадением | 0,228 | 0,012 | -94,7% |
| Посчитать срабатывания по 120 измерениям | 0,786 | 0,098 | -87,5% |
| Получить итог по четырём агентам | 0,192 | 0,093 | -51,6% |
| **Все 6 000 выполнений** | **15,008** | **1,346** | **−91,0%** |

В отдельном журнале из 200 000 строк ответ «200 совпадений» занял **12 токенов** против **542** с выдержками. Для журнала из 100 000 строк оптимизированная команда вернула тот же фрагмент за **40,9 мс** вместо **178,0 мс**. Это медиана по 21 паре запусков на macOS. [Замер поиска](docs/benchmarks.md#searching-200000-lines) · [Замер времени](docs/benchmarks.md#previewing-100000-lines)

## Инструменты

| Инструмент | Как работает и зачем нужен |
|---|---|
| `context.py run` | Запускает команду, сохраняет stdout и stderr, возвращает код завершения и основные сообщения об ошибках. Подходит для сборок и тестов с длинным выводом. |
| `view.py` · `harness_view` · `harness_find` | Показывает пронумерованные строки или выбранные поля JSON. Поиск по точному тексту возвращает фрагменты с соседними строками или только число совпадений. Подходит для вопросов по одному файлу. |
| `context.py map` · `harness_code_map` | Находит файлы по словам запроса и показывает наиболее подходящие места с путями и номерами строк. Чтобы прочитать Java-метод и его перегрузки, `context.py symbol` использует необязательный парсер Tree-sitter. |
| `history.py budget` · `harness_context_budget` | Сопоставляет стоимость сводки и повторного чтения деталей со стоимостью передачи истории в следующих запросах. Помогает выбрать момент для сжатия. |
| `context.py reuse` · `context.py build-check` | Первая команда сравнивает контрольные суммы входных данных и сохранённых результатов. Вторая сопоставляет имеющиеся проверки с конкретной сборкой. Помогают избежать лишних прогонов. |
| `metrics.py --summary` · `harness_metrics` | Читает временной ряд локально и возвращает покрытие, пропуски, пик и число срабатываний. Помогает узнать, сколько раз показатель достиг порога в большом отчёте. |
| `team.py` · `team.py usage` | Доска хранит ответственных, передачи задач и результаты проверки. Отчёт собирает зарегистрированные входные, кэшированные и выходные токены выбранного чата и его локальных агентов. |
| `context.py audit` · `harness.py doctor` | Первая команда находит повторы в инструкциях и показывает настроенные MCP-серверы. Вторая показывает регистрацию хуков и полученные от них события. Пригодятся при диагностике подключения. |

## Другие клиенты

Установщик также поддерживает Claude Code и Gemini CLI. Для OpenCode есть плагин. В MCP-клиенте с транспортом stdio укажите исполняемый файл Python как команду, а абсолютный путь к `loomharness/scripts/mcp_server.py` как аргумент. Через MCP доступны пять инструментов с префиксом `harness_*` из таблицы. [Подключение и поддержка клиентов](integrations/README.md)
