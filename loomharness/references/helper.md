# Локальные проверки

## Диагностика хуков и SSH

`harness.py status` показывает сохранённый выбор проекта. Запусти `harness.py doctor` в рабочей папке того чата, который должен получать события. В JSON есть хост, путь, вид подключения, собственный `session` чата и `projectEnabled`. Поле `codexRegistry` содержит результат запроса `hooks/list` к новому процессу Codex для этой папки, со статусами `enabled` и `trustStatus` каждого обработчика. Пустой список означает ноль регистраций LoomHarness, `unavailable` означает ошибку запроса. Путь к бинарнику приложения можно передать через `--codex ПУТЬ`.

В `userHookFile` видны объявления из пользовательского `hooks.json`, в том числе на хосте, где Codex CLI недоступен. `lastHook` показывает последнее зарегистрированное событие с временем UTC для этой папки и сессии. `null` означает отсутствие наблюдения. Учитываются события начала, запроса пользователя, остановки и проверяемые действия. Обычные вызовы инструментов проходят быстрый фильтр. Запись содержит только имя события, клиент, время, рабочую папку и идентификатор сессии.

Если Codex запущен на Mac или Linux, а проект находится на Windows, выполни `doctor` на обоих хостах. Для Windows используй клиент из локальной установки LoomHarness. Ему нужны OpenSSH с проверенным ключом хоста и доступный на Windows `python`. Запускай его из своего чата, чтобы он передал его идентификатор.

```sh
sshkit="$HOME/.agents/skills/loomharness/scripts/ssh_windows.py"
python3 -I -X utf8 "$sshkit" --project 'C:\Work\Project' win-host harness doctor
python3 -I -X utf8 "$sshkit" --project 'C:\Work\Project' win-host team intake
python3 -I -X utf8 "$sshkit" --project 'C:\Work\Project' --steps steps.json win-host
```

Файл `steps.json` содержит массив команд, например `[["team","intake"],["team","inbox","--watch"]]`. Первая ошибка останавливает очередь. Диагностика на stderr указывает номер шага и исходный код. Коды 1–255 возвращаются вызывающему процессу, более крупный код Windows преобразуется в 1. Ошибка соединения OpenSSH обычно возвращает 255. Параметр `--ssh-config` выбирает профиль OpenSSH, `--scripts` задаёт абсолютный каталог скриптов на Windows. Все аргументы передаются буквально.

## Чтение доказательств

Для документов, таблиц и внешних сервисов подтверждением служит проверяемый результат в его обычной среде. Для локальной отметки можно прочитать сохранённый отчёт или текстовую выгрузку с источником, версией и наблюдаемым результатом. Дополнительные файлы состояния задаются через `state_files` в [настройках проекта](verification.md).

На Windows запускай помощник из рабочей папки в PowerShell.

```powershell
$kit = Join-Path $env:USERPROFILE '.agents/skills/loomharness/scripts/harness.py'
python -I -X utf8 $kit enable
python -I -X utf8 $kit disable
python -I -X utf8 $kit status
python -I -X utf8 $kit read 'logs/проверка.log' --find 'CHECK'
python -I -X utf8 $kit read 'logs/проверка.log' --start 120 --lines 20
```

На macOS и Linux те же команды доступны через Python 3.

```sh
kit="$HOME/.agents/skills/loomharness/scripts/harness.py"
python3 -I -X utf8 "$kit" enable
python3 -I -X utf8 "$kit" disable
python3 -I -X utf8 "$kit" status
python3 -I -X utf8 "$kit" read 'logs/проверка.log' --find 'CHECK'
python3 -I -X utf8 "$kit" read 'logs/проверка.log' --start 120 --lines 20
```

`enable` и `disable` запоминают выбор в пользовательских настройках Codex по пути проекта. В Git используется корень текущего рабочего дерева. Ранее созданный маркер `.codex/harness.enabled` означает «включено», пока пользователь не изменил решение. На вопрос LoomHarness в этом чате можно ответить «да» или «нет», на английском — `yes` или `no`. Прямые команды `LoomHarness on` и `LoomHarness off` работают на любом языке. Сообщения «Включи хуки LoomHarness» и «Отключи хуки LoomHarness» также меняют выбор (прежние фразы с «харнесс» продолжают работать).

## Установка хуков в другие CLI

Установщик регистрирует те же четыре обработчика в любом поддерживаемом CLI: `python -X utf8 install.py --cli claude` (Claude Code, `~/.claude/settings.json`), `--cli gemini` (Gemini CLI, `~/.gemini/settings.json`) или `--cli all` для всех найденных. Гейт доказательств при этом действует и на прямые редакторы этих CLI: Edit/Write/MultiEdit у Claude Code, write_file/replace у Gemini CLI. `status` показывает выбор и Git. `read` читает текстовое доказательство и отмечает чтение для текущего чата и рабочей папки на 30 минут (по умолчанию 40 строк, при `--find` 12). Поиск по буквальному тексту учитывает регистр. Он выводит до 12 совпадений с исходными номерами строк и указывает, с какой строки продолжить. Отсутствие совпадений возвращает ошибку. Для чтения соседних строк используй `--start 120 --lines 20`. Для форматов PDF, изображений или таблиц используй профильный просмотрщик и приложи текстовый результат проверки. Сводка и сам редактируемый файл состояния доказательством собственной корректности не служат.

Модель для запрошенного разбора на чтение хук берёт из поля `read_review` в `$CODEX_HOME/loomharness/delegation.json`. При отсутствии настройки используется модель по умолчанию.

## Self-update

`python harness.py update` сверяет установленную копию с git-источником; результат кэшируется на сутки, поэтому обычный вызов ничего не скачивает. `--set-origin URL [--branch main]` настраивает источник, `--apply` применяет обновление (только когда на досках нет активных поручений, с проверкой компиляции и резервной копией), `--rollback` возвращает прежнюю версию. Git-копия обновляется `pull --ff-only`; обычная папка — клоном с проверкой `py_compile`, прежняя копия в `$CODEX_HOME/loomharness/backups/`.

## Headless-драйверы выдачи

По умолчанию `dispatch` возвращает операции чатов приложения Codex (create_thread/send_message_to_thread). Команда `python team.py driver set claude|gemini|antigravity|opencode|dsh` переключает доску на headless-драйвер: dispatch вернёт `run_command`, который координатор выполняет штатным инструментом shell — скрипт `scripts/team_driver.py` соберёт промпт из карточки, запустит выбранный CLI в папке проекта, полный журнал сохранит в `.loomharness/runs/`, а на stdout даст сводку с использованием токенов, если CLI её отдал в JSON. `team.py driver set desktop` возвращает исходный режим, `driver show` показывает текущий. Доступные модели опрашивает `python team_driver.py models`; запись быстрой модели проекта (её допуск решают слепые испытания): `python team_driver.py models --apply --routine ИМЯ` (пишет `.codex/harness-models.json`).

## Быстрый процесс доски

Для активного проекта можно держать один процесс доски вместо процесса на каждый вызов: `python team.py serve` (порт записывается в `$CODEX_HOME/loomharness/serve.port`, завершение — строка `quit` на stdin или остановка процесса). Команды тогда идут через `python scripts/hk_call.py --project ПУТЬ КОМАНДА …` или `python team.py rpc`. Для разовых вызовов прямой CLI столь же быстр — эффект дают пакетные и многокомандные сессии.

Обновление запускается командой `harness.py update`: без флагов — тихая проверка (кэш сутки, ничего не скачивает), `--force-check` — проверка без кэша, `--apply` — применить найденное, `--rollback` — вернуть прежнюю версию. Источник обновления задаётся `update --set-origin URL [--branch main]`.

Файл AGENT_STOP в корне проекта останавливает активность: новые вызовы инструментов отклоняются (включая правку файлов), оставь состояние в чате. Продолжение возможно, когда владелец уберёт файл. При ответе «нет» на вопрос о хуках веди задачу в обычном режиме; до явной смены выбора автоматические проверки выключены. Перед правкой файла состояния (`STATE.json`, `features.json`, `test-results.json` или настроенных `state_files`) в этом чате сначала прочитай доказательство командой `read` выше. Остальное поведение хуков модель получает из самих хуков при старте и завершении хода.
