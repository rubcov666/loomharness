# run, audit и map

Команды `context.py`: запуск с сохранением лога, аудит инструкций и карта исходников. Пути к скрипту и примеры запуска — в [context.md](context.md), чтение доказательств — в [helper.md](helper.md).

**run.** После двойного дефиса укажите исполняемый файл и отдельные аргументы. Для сценария оболочки укажите её явно. Используйте новый путь в существующей локальной папке для логов. Команда сохраняет исходные stdout и stderr и передаёт код завершения. Сводка считает узнаваемые строки успешных тестов unittest, pytest и Rust, а также шаги сборки Ninja. Длинные журналы показываются с номерами строк, диагностикой и концом вывода. Диапазон `10-24: waiting` означает, что текст повторился на каждой из этих строк. Различия в конце длинной строки учитываются до обрезки. Если в журнале до 4 КиБ сокращение скрыло бы подробности, он выводится целиком. REVIEW обозначает сокращённые детали. Для поиска всех ошибок, перед зачётом результата с REVIEW или при неясной причине откройте нужный фрагмент исходного лога. Для зачёта нужны ожидаемые проверки и итог. Нулевой код возможен при пропусках и при отсутствии тестов. Лог можно читать фрагментами [через помощник](helper.md).

**audit.** Запускайте из той папки, в которой открывается чат. Команда читает эффективную конфигурацию локального Codex CLI, сверяет файлы с локальным предпросмотром инструкций и показывает имена настроенных MCP и пары одинаковых строк. Если версия CLI не поддерживает предпросмотр, отчёт помечается как оценка. Учитываются глобальный файл, корень проекта, вложенные папки до текущей, приоритет AGENTS.override.md, запасные имена и предел байтов проекта. Совпадения короче 24 знаков опускаются. Отчёт служит для ручной ревизии. Одно и то же правило иногда нужно в двух самостоятельных проектах. Плагины приложения и инструкции, переданные самим чатом, находятся за пределами отчёта.

**map.** Ищите по словам в текстовых файлах UTF-8 любого расширения, включая файлы без расширения. Карта показывает путь, номер строки и распознанное имя объявления, если оно есть. В Git используется список отслеживаемых и новых файлов с правилами исключений репозитория. В обычной папке используется список ripgrep. Если ripgrep отсутствует, помощник обходит доступные файлы и пропускает скрытые папки, ссылки, node_modules и __pycache__. В таком режиме файлы исключений Git и ripgrep не применяются. Двоичные файлы и файлы больше 1 МиБ не участвуют в поиске. Документы со сложным форматом открывайте в их приложении.
## Проверка сборки и чтение методов

Для сохранённых тестов используй `context.py build-check evidence/validation-index.json --artifact dist/app.jar`. Вместо файла сборки можно передать известный `--revision SHA256` или `--build-report build.json` с полем `candidateSha256` и необязательным `runtimeSha256`. При наличии обоих они должны совпасть. В ответе есть SHA, число успешных, упавших, пропущенных и неподтверждённых прогонов, число успешных утверждений, первая проблема и путь к полному отчёту.

В индексе укажи `revision` и массив `runs`. Для каждого прогона передай его собственные `revision`, `label`, `exit` и положительное свидетельство (`passes`, строку `PASS` в `assertions` или `status: passed`). Поддерживаются поля `releaseJar` и `jar` для архивов Java. `status: skipped`, отсутствующий код завершения и строки `errors` остаются видимыми. Используй повторяемый `--require LABEL`, если критерий приёмки задаёт обязательные тесты. Код возврата 0 означает успешные проверки выбранной ревизии, 1 — сбой команды или проверки, 2 — неполные либо несогласованные данные.

Для повторяющегося цикла запусти `context.py build-check --recipe check.json --require smoke`. Пути и команды относятся к папке рецепта. В этом примере проект предоставляет скрипты сборки и тестов.

```json
{
  "artifact": "dist/app.jar",
  "build": ["python", "build.py", "{artifact}"],
  "test": ["python", "test.py", "--jar", "{artifact}", "--sha", "{revision}", "--report", "{index}"]
}
```

Тест записывает свежий индекс в переданный путь. Команда сохраняет полные журналы сборки и тестов в отдельной папке `.loomharness/logs/` и сверяет SHA артефакта до и после проверки.

Для обычного поиска начни с `rg -n`. Если нужны полные определения и все перегрузки, используй `context.py symbol src/Catalog.java Catalog.lookup`. Команда разбирает только указанный файл. Для неё в выбранном Python нужны пакеты `tree-sitter==0.25.2` и `tree-sitter-java==0.23.5`. Для точных межфайловых ссылок используй поиск ссылок в языковом сервере проекта или `find_referencing_symbols` в уже настроенной Serena. [Serena](https://github.com/oraios/serena)
