# Передача результата

Приёмка — в [review.md](review.md), порядок координатора — в [organization.md](organization.md).

После приёмки координатор поручает общую передачу одному чату через `delivery ID [ID ...] --revision ХЕШ --target "точное назначение" --action prepare`. Он может подготовить пакет и инструкцию. Для фактической передачи используй `--action publish --effects handoff --authority "ссылка на поручение владельца"`. Если пользователь отдельно поручил действия с Git или действующим сервисом, укажи соответствующие эффекты `git` и/или `service` и их точную цель. Ответ о необходимости Git сам по себе не разрешает публикацию. Учитывай принятые в организации правила доступа и подтверждения.

В пакет попадает только согласованная версия. Если одобрены отдельные изменения с разными хешами, заведи зависимую интеграционную карточку для совместной сборки или итогового архива, проверь объединённый результат и передай его отдельным выпуском. Очередь выпуска последовательная. Исполнитель делает `job-claim`, сверяет реальный адрес, версию, состояние предыдущей попытки и готовность к восстановлению для изменяемого сервиса. После действия проверь результат в месте назначения: скачанный файл и его хеш, состояние версии в системе или доступность приложения. Зафиксируй `delivered JOB БИЛЕТ "что и где подтверждено" --revision ХЕШ`.

Если результат внешнего действия неизвестен, оставь задание активным, сверь состояние в месте назначения и сообщи координатору. Для разбора служит `job JOB`. При подтверждённой отмене координатор может снять задание через `job-cancel JOB "проверенный исход"`. Пользовательские разрешения на доступ, правила Git-хостинга и права на запуск сервисов применяются самим инструментом в месте выполнения.
