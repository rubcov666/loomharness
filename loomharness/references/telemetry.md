# Числовые наблюдения по окнам

Для повторных проверок расхода добавь `--summary` к `team.py usage`. В отчёте за окно останутся суммарные счётчики, число участников, границы и пробелы покрытия. Для сравнения участников используй полный вывод. На доске короткий отчёт также сохраняет время до приёмки.

Для оценки полного поручения укажи корневой чат и границы окна с часовым поясом, например `team.py usage --thread ID --since 2026-01-01T10:00:00Z --until 2026-01-01T11:00:00Z`. Команда читает локальный индекс дочерних агентов и их собственные записи расхода. Для отдельных постоянных чатов команды повтори `--thread`. Левая граница входит в окно, правая исключается. В отчёте видны обращения модели, кэшированный и новый вход, выход, участники и пробелы покрытия. Сравнивай одинаковые задания и ревизии. Время от выдачи до принятия берётся из `team.py usage` на доске, поле `dispatch_to_accept`.

Для локального экспорта передай инструменту `harness_metrics` путь к JSON. Например, `{"path":"/project/samples.json","threshold":2000,"summary":true}`. Параметр `root` ограничивает чтение указанным каталогом. Небольшой ряд можно передать сразу в `data`.

Если нужны покрытие, пустые окна, пик и число срабатываний, укажи `summary: true` в MCP или `--summary` в CLI. Поля `alert_count` и `outside_alert_count` дают число срабатываний внутри и вне окон. Режим по умолчанию возвращает отдельные наблюдения для разбора.

Если нужен точный ответ о пороге, пике или пустых интервалах, используй `scripts/metrics.py данные.json --at-least 2000`. Вместо файла можно передать `-` для stdin. Вход содержит массив `windows` с полями `start`, `end` и необязательным числом строк `expected`, а также массив `samples` с полями `at` и `value`. Время записывается в ISO 8601 с часовым поясом. Окна включают начало и заканчиваются перед указанной границей. Например, `{"windows":[{"start":"2026-01-01T09:00:00Z","end":"2026-01-01T09:01:00Z","expected":1}],"samples":[{"at":"2026-01-01T09:00:00Z","value":2000}]}`.

В ответе есть количество измерений в каждом окне, пустые окна, пик, все значения на пороге и выше, а также отдельные события вне окон. Пустое окно означает отсутствие наблюдения. Для вывода о причине открой первичные данные. Повтор временной отметки, неизвестная схема или расхождение с заявленным числом строк останавливают подсчёт с ошибкой. Проект может преобразовать свой экспорт в этот формат на месте.
